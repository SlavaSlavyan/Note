# Задание 1. Рассказать про 4 принципа ООП

Четыре главных принциппа Обьектно Ориентированного Программирования это:

- инкапсюляция;
- наследование;
- полиморфизм;
- абстракция;

Нужно это ваше ООП для **структуризации кода** *(чтобы было хоть какое-то устройство программы, а не 1001 функция)*, **легкой поддержки кода** *(Гораздо легче перенести код на новые платформы или на новые версии если использовалось ООП)* и **маштабируемости кода** *(добавить новую функцию легче в класс чем в глобальное пространство ¯\\\_(ツ)_/¯)*

Давайте рассмотрим каждый принципп отдельно.

## 1. Инкапсуляция

Если есть какая либо вещь над которой работают несколько функций, или она включает в себя несколько разных функций - то их можно обьединить в класс. Но такие вещи как реализацию лучше скрывать от чужих глаз и защищать. Для этого придумали **инкапсуляцию** которая помогает выделять разную видимость нашим полям и методам внутри класса *(public, protected, private)*. Вы можете быть очень крутым программистом который знает устройство проекта в плоть до каждой отдельной переменной, но даже так есть большая вероятность накосячить и изменить то, что изменять лучше не стоит. ЗАЩИЩАЙТЕ КОД!

Вот пример инкапсуляции на основе Банковского аккаунта.

```cpp
class BankAccount {
private:
    double balance; // Скрыто от прямого доступа

public:
    BankAccount(double initialBalance) : balance(initialBalance) {}

    // Метод для безопасного доступа к приватным данным
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    double getBalance() const {
        return balance;
    }
};
```

Сам баланс закрыт от прямого воздействия. Взаисодействие с аккаунтом происхоит через программируемые методы, что предотвращает ошибки.

## 2. Наследование

Некоторые классы могут быть очень похожими на друг друга и отличаться лишь маленькими деталями. Вместо того чтобы постоянно писать новые классы мы лучше просто сделаем **наследование**. При насследовании класса потомок уже умеет всё то что умеет его родитель. Остаётся лишь добавить свои методы или даже переписать некоторые базовые.

Пример с животными.

```cpp
#include <iostream>
#include <string>

// Базовый класс
class Animal {
public:
    void eat() {
        std::cout << "Этот зверь ест.\n";
    }
};

// Производный класс
class Dog : public Animal {
public:
    void bark() {
        std::cout << "Гав-гав!\n";
    }
};
```

У нас есть базовый класс для всех животных который умеет есть *(каждое животное ведь ест)* и его потомок - собака, которая теперь умеет ещё и гавкать.

## 3. Полиморфизм

Чёт я понял что немного проебался и про полиморфизм написал в прошлом под-пункте, но ещё раз. **Полиморфизм** позволяет классам отделять реализацию от методов. Реализовать можно всегда по своему, а метод - един! Переопределение методов является примером полиморфизма.

Пример с системой сотрудников

```cpp
class Employee {
public:
    virtual void work() const {
        std::cout << "Выполняет общую работу.\n";
    }
    virtual ~Employee() {} // Виртуальный деструктор для базовых классов
};

class Manager : public Employee {
public:
    void work() const override {
        std::cout << "Управляет проектом.\n";
    }
};

// Функция, демонстрирующая полиморфизм
void makeThemWork(const Employee& emp) {
    emp.work(); // Вызовет правильный метод в зависимости от типа объекта
}
```

Тут мы берём базовый класс **Employee** и переопределяем метод работы в наследнике **Manager**. Вроде бы функция таже самая, но выполняет теперь совсем другую работу.

## 4. Абстракция

**Абстракция** всегда являлась частью программирования, ведь думать о нулях и единичках не всегда приятно. В С++ абстракцию вывели на новый уровень. Теперь мы ВООБЩЕ не думаем о реализации или каких либо других моментах, намечая только самое основное и уже ПОТОМ доделывая саму реализацию. 

Пример с фигурами

```cpp
class Shape {
public:
    // Чисто виртуальная функция делает класс абстрактным
    virtual double getArea() const = 0; 
    virtual ~Shape() {}
};

class Circle : public Shape {
private:
    double radius;
public:
    Circle(double r) : radius(r) {}
    
    // Реализация абстрактного метода
    double getArea() const override {
        return 3.14 * radius * radius;
    }
};
```

В **Shape** мы задаём "абстрактный" метод получения площади который ме реализуем только в наследнике **Circle**
