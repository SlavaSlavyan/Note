Виды архитектур БД:
1. Централизованная архитектура - это система где все данные хранятся в едином пространстве, управляемом центральным сервером. Такая архитектура обеспечивает единообразное хранение и обработку информации. через централизованный механизм контроля доступа.
	* Принцип работы - все операции с БД, пользовательские интерфейсы и приложения управляются одним центральным компьютером (сервером). Пользователь (клиенты) обращаются к серверу для доступа к данным и манипулирования ими. БД может располагаться на одном ПК, который может не иметь поддержки сети и работать автономно. В этом случае работа в БД возможна только локально. Если компьютер работает в сети, доступ к информации может осуществляться удалённо с других компьютеров в сети.
	* Плюсы:
		* высокий уровень безопасности данных (когда информации сосредоточена в одном месте, проще контролировать доступ и предотвращать несанкционированные действия);
		* упрощённое резервное копирование и восстановление данных;
		* простота администрирования;
		* экономическая эффективность;
	* Минусы:
		* риск отказа системы (если сервер выходит из строя, то вся система становится недоступной);
		* проблемы с масштабируемостью (по мере роста числа пользователей сервер может с трудом справляться с выросшей нагрузкой)
		* зависит от сетевой инфраструктуры

2. Архитектура файл-север - это подход к организации хранения данных в информационных системах, основанный на клиент-серверной модели взаимодействия. Централизованный элемент - это специализированный сервер отвечающий за хранение и управление файлами.
	* Принцип работы:
		1. Клиент отправляет запрос на доступ к файлу через прикладную программу находящуюся на его ПК.
		2. Программа отправляет запрос в СУБД.
		3. СУБД запрашивает необходимые данные у БД, находящейся на файловом сервере.
		4. Сервер отвечает и отдаёт запрашиваемые файлы в СУБД и в прикладную программу.
	* Плюсы:
		* масштабируемость (можно увеличить количество пользователей, которые будут использовать БД);
		* централизованное управление (администратор может контролировать все аспекты работы с файлами из единой точки);
		* безопасность (появляются механизмы авторизации и аутентификации);
		* единая точка резервного копирования;
	* Минусы:
		* сложность обеспечения целостности и согласованности данных (если несколько клиентов одновременно пытаются изменить одни и те же данные - возникает риск конфликтов и несоответствия данных);
		* высокая сетевая нагрузка (при большом количестве одновременно работающих пользователей, отправляющих запросы на сервер происходит высокая сетевая нагрузка);
		* потенциальная точка отказа (если у нас откажет сервер на котором хранятся данные, БД не будет работать, но СУБД будет работать)

3. Архитектура клиент-сервер - предполагает наличие некоторого наличия компьютеров, объединённых в сеть, один из которых выполняет особые управляющие функции (Является сервером сети). Такая архитектура разделяет функции приложения пользователя и сервера. Приложения-клиент формируют запрос к серверу, на котором расположено БД на языке запросов SQL. Является промышленном стандартом в мире реляционных БД.
	* Плюсы:
		* масштабируемость (можно увеличить количество пользователей, которые будут использовать БД);
		* централизованное управление (администратор может контролировать все аспекты работы с файлами из единой точки);
		* безопасность (появляются механизмы авторизации и аутентификации);
		* гибкость (легко добавлять новые функции без значительных изменений);
		* обновляемость;
	* Минусы:
		* зависит от сервера;
		* сложность настройки;
		* сетевые задержки;
		* стоимость;
		* уязвимость к атакам;

4. Трёхзвенная (многозвенная) архитектура клиент-сервер - данная архитектура представляет собой дальнейшее совершенствование архитектуры  клиент-сервер. В трёхзвенной архитектуре вся бизнес-логика ранее входящая в клиентские приложения выделяется в отдельное звено, называемым сервером приложений. При этом клиентским приложениям остаётся лишь пользоваться интерфейсом.
	* Плюсы:
		* масштабируемость (можно увеличить количество пользователей, которые будут использовать БД);
		* управляемость (разделение на уровни упрощает управление разных систем, легко изменить один уровень не затрагивая другой)
		* безопасность (появляются механизмы авторизации и аутентификации);
		* гибкость (легко добавлять новые функции без значительных изменений);
	* Минусы:
		* затраты на инфраструктуру;
		* задержка в обработке запросов;
		* сложность разработки;
