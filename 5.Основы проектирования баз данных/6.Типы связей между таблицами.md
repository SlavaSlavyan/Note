В реляционной БД между сущностями есть связи.
Существует несколько видов связей:
- 1 ко многому(1-n)
	- 1 владелец много машин
- 1 к 1(1-1)
	- одна вещь принадлежит одному человеку(человек и медполис)
- многое ко многому(n-n)
	- авторы и книги
В БД связи между сущностями помогают организовать информацию
Ключевые моменты целостности данных:
	1. Первичный ключ должен быть уникальным. Первичный ключ - это уникальный идентификатор каждой записи(кортеж). Он может состоять из цифр и букв. В таблице клиент у каждого клиента есть уникальный номер(1). Этот уникальный номер и есть первичный ключ. Он должен быть обязательно у каждого клиента и не должен повторяться. Если добавить клиента уже с существующим ID, база данных должна выдавать ошибку
	2. Внешний ключ ссылается на существующий ID, т.е. на первичный ключ. В таблице заказов есть столбец, указывающий какой клиент сделал заказ(по ID клиента) это будет внешним ключом. Он должен содержать только те ID клиентов, которые уже есть в таблице клиентов. Нельзя указать несуществующего клиента
	3. Защита от ошибок. Если правильно созданная БД, то она не позволит вам, добавлять клиентов с повторяющимся ID, указать для заказа, несуществующий ID клиента. Если удалить клиента, который уже делал заказы, тогда БД выдаст ошибку, но БД можно настроить автоматическое удаление, связанных заказов тогда БД не будет ругаться и вы сможете удалить клиента
	4. Нарушение целостности. Если БД не контролирует эти правила, то нарушится целостность данных и в последствии данные станут противоречивы и ненадёжными
